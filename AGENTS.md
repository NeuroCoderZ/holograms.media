Любая постановка задачи, исходящая из того, что человек читает голограмму глазами, ошибочна по построению.**

2026-09-27 06:05 MSK — **1. Голографические медиа — НЕ просмотрщик голограмм.** Это носитель, в котором звуковой поток закодирован в видимую трёхмерную структуру **для машинного зрения**. Читатель голограммы — камера (устройства или XR-очки), которая декодирует её обратно в звук.

2026-09-27 06:05 MSK — **2. Человек — АВТОР, а не читатель.** Он задаёт, как будет звучать место или предмет, и не обязан ничего различать на экране. Глаза видят общую картину, потому что видят то же, что слышат уши, и мозг сопоставляет одно с другим.

2026-09-27 06:05 MSK — **3. Цель — перепрограммировать физический звуковой мир** поверх неизменного визуального представления реальности. Эталон: голограмма «оживлена» поверх 3D-копии калитки; камера видит движение створки, и в уши надевшего очки идёт мычание коровы, привязанное к скорости и степени завершённости хода, тогда как все вокруг слышат настоящий скрип.

2026-09-27 06:05 MSK — **4. ЗАПРЕТ: визуально-геометрическое изменение голограммы как объекта НЕ ЯВЛЯЕТСЯ ЦЕЛЬЮ.** Красота, цвет и форма несут смысл только как АДРЕС и как форма визуального источника звука. Любая задача, начатая с «улучшить внешний вид голограммы», направлена мимо задачи и должна быть отклонена.

2026-09-27 06:05 MSK — **5. Голограмма есть анимированный QR-код для звука.** Голокадр незвучен (как одиночный сэмпл) — минимальный носитель есть голомация. Диапазон кодера покрывает перцептивный конверт целиком: 16,352…25 088,32 Гц (инфразвук…ультразвук) и 128 уровней по 1 дБ (порог слышимости…порог боли).

2026-09-27 06:05 MSK — **6. Earth_0 и Своя атмосфера.** Earth_0 — общая универсальная Земля, прозрачная и медленно меняющаяся. Своя атмосфера — персональный слой поверх неё, разбитый на кубики, каждый из которых наделяется свойством звучания и видимости посредством жестов. Область действия личной атмосферы — только там, где пользователь есть сейчас и где был ранее (след, а не пузырь). Атмосферы смешиваются и рециркулируют друг в друга через NetHoloGlyph.

2026-09-27 06:05 MSK — **7. Разделение слоёв — ПО УСТРОЙСТВУ, а не по камере.** У каждого свои очки и наушники, поэтому в своей копии Земли кубы программируются как угодно и БЕСПЛАТНО (за вычетом электроэнергии). Платить нужно только за ПРИГЛАШЕНИЕ другого, потому что тогда оплачивается чужое оборудование и чужие XR-очки. Принцип масштабирования: «вещаю = плачу токены».

2026-09-27 06:05 MSK — **8. Шестая ступень — ГОЛОКОНТРАКТ.** Каждый жест есть контракт со средой. Контракт исполняется НЕПРЕРЫВНО («пока(створка идёт) { звук = f(фаза, скорость) }»), то есть это подписка на поведение, а не транзакция. Газ здесь — не вычисления, а звук. Нотариусом служит сама голограмма: две камеры на один куб читают один контракт, доверенная третья сторона не нужна. **Голограмму переслать нельзя (привязана к месту и моменту), а контракт можно прислать кому угодно, и у него зазвучит.**

2026-09-27 06:05 MSK — **9. Токеномика внимания.** Тот, кто генерирует, ПЛАТИТ тому, кто внимает. Внимание — единица учёта, оплачивающая сразу три вещи: вычисления (чужое оборудование), верификацию (внимание есть доказательство восприятия) и труд (внимательный пользователь может модифицировать и ответвить работу). Это обратная сторона банковской инфраструктуры, остающаяся той же экономикой. Полный цикл: создатель верифицирует инфраструктуру и приглашает других, платит им за внимание; если им понравилось, они используют его наработки, привлекают других и зарабатывают на фидбэке, а ему отходит процент.

2026-09-27 06:05 MSK — **10. Версия куба определяется вниманием большинства** — статистическим голосованием, по образцу формирования спроса просмотрами на YouTube. Каждый куб подписывается разными пользователями в разное время, и пользователь сам выбирает версию, которую хочет видеть и слышать сейчас. **Идентичность привязана ко времени.** Разрешение противоречий между слоями в общей Earth_0 — задача Глобальной Триа.

2026-09-27 06:05 MSK — **11. Квант изменяемости = 22 мин 23 с** (Земля при 29,78 км/с проходит округлённый диаметр 40 000 км). Второй квант — 24 часа. Локальные изменения живут в первом, устойчивые — во втором.

2026-09-27 06:05 MSK — **12. Персональная и Глобальная Триа.** Персональная Триа — голографический интеллектуальный представитель пользователя, завязанный на его цифровой кошелёк. Глобальная Триа существует между персональными и служит сетевым координатором, централизованным банком и гигантской жестовой библиотекой смыслов; синхронизирует координацию, донастройку, докалибровку и синестезию представления. Связность персональных Триа устроена по законам композиции сервисов — тем же, что связывают агенты в DeepSeek Harness.

2026-09-27 06:05 MSK — **13. Триа НЕ МОЖЕТ стоять в горячем пути «кадр → звук»** — облачный вызов LLM стоит 300–2000 мс, что при 60 Гц даёт 18–120 выпавших кадров. Контур A (ухо) работает каждый кадр без сети, ~7,5 мс из 16,67 мс. Контур B (мозг) — 2–10 Гц, асинхронно, достраивает то, чего в картинке физически нет (фаза, микроструктура, обертоны).

Все проверки, билды и валидации выполняются ТОЛЬКО в CI/CD (GitHub Actions → Cloudflare Pages / Koyeb). Агенты работают исключительно через `git push` и мониторинг ранов.
9. **Hermes Family:** Core (Meta-Agent/Router), Behavior (Gestures/Clicks), Context (Docs/Code), Memory (AstraDB), Wallet (Obolos/Energy/LLM Cost).
10. **Hermes Router Architecture:** Гермес — оркестратор, не генератор. Классифицирует интенцию → выбирает лучшую LLM → оценивает стоимость → диспатчит запрос → агрегирует ответ. Поддерживает multi-LLM параллельные консультации.
11. **Currency Rates:** Гермес всегда знает актуальные курсы TON/USD/RUB через CoinGecko API + ExchangeRate API. Кэширует в KV + Memory.
12. **Contract State Machine:** Гермес ведёт клиента по фазам (draft → review → sorting → agreement → escrow). Каждая фаза имеет опорные фразы, условия перехода, цели.

## Единый деплой / мониторинг (что должны знать агенты)

### 1) Единый деплой — `scripts/deploy.js`
Агенты должны запускать обновления проекта через **одну команду**:
- `node scripts/deploy.js "Описание изменений"`

`deploy.js` выполняет в этом порядке:
1. *Frontend build выполняется на стороне CI/CD (Cloudflare/GitHub Actions); локальный запуск `npm run build` запрещён.*
2. pre-deploy checklist (`node scripts/pre-deploy-check.js`)
3. генерацию контекста репозиториев (`npx repomix` и `neuroescrow/repomix-output.md`)
4. bump версии (`version.txt`, `package.json`, `index.html`) через `node scripts/generate_version.js`
5. деплой NeuroEscrow Hermes в Cloudflare Workers (`wrangler deploy`)
6. `git add` → `git commit` → `git push origin dev`

### 2) Почему GitHub UI показывает “старые билды”
workflow на GitHub Actions стартует **не от локального build**, а от **push/commit** в ветку, соответствующую CI.
Значит: если изменений не коммитили/не пушили — новые runs на GitHub не появятся.

### 3) Контекст для двух Hermes обновляется через CI-пайплайн
Обновления для гермесов (core/behavior/context/memory) получают актуальный контекст после деплой-события, потому что пайплайн использует:
- версионные изменения (bump)
- сгенерированный RepoMix контекст (репозиторный “код→знания”)
- push в `dev` (триггер workflows)

### 4) Самописный монитор — `scripts/monitor-server.js`
Для контроля процесса и статуса используется:
- `node scripts/monitor-server.js` → http://localhost:3001

Монитор читает агрегированные данные через endpoint’ы (`/api/status`) и отображает сборку/деплой/логи, а также управляет “копированием логов” только после того, как данные реально загружены (не по хрупким подстрокам).

*"Архитектура следует за интенцией. Код — это геометрия резонанса."*
