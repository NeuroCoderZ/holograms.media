# 🚫 КРАСНЫЕ ЗОНЫ AI-КОДА (Security Zones)

## Дата создания: 13.05.2026
## Версия: 1.0.0

---

## 📜 Философия

**Красные зоны** — это критические участки кодовой базы, модификация которых может привести к:
- Утечке секретов (API keys, tokens, credentials)
- Нарушению аутентификации/авторизации
- Повреждению данных (AstraDB, user sessions)
- Сбою деплоя/CI/CD пайплайна
- Финансовым потерям (платежи, escrow)

**Правило:** Агенты (AI-ассистенты) могут **читать** эти файлы для понимания архитектуры, но **НЕ МОГУТ модифицировать** без явного `✅ Принято` от НейроКодера.

---

## 🔴 СПИСОК КРАСНЫХ ЗОН

### 1. **Аутентификация и авторизация**
**Путь:** `backend/auth/`

**Файлы:**
- `backend/auth/security.py` — JWT, OAuth, Google Sign-In
- `backend/auth/middleware.py` — проверка токенов
- `backend/auth/permissions.py` — RBAC, whitelisting

**Правила:**
- ✅ **Чтение разрешено** — для понимания flow аутентификации
- ❌ **Модификация запрещена** — без явного `✅ Принято`
- ⚠️ **Копирование паттернов** — требует review (риск дублирования уязвимостей)
- 🚫 **Логирование секретов** — абсолютно запрещено (JWT, refresh tokens, OAuth secrets)

**Примеры запрещённых действий:**
- Изменение алгоритма JWT (`HS256` → `none`)
- Добавление новых эндпоинтов без CSRF protection
- Ослабление валидации токенов
- Хардкод секретов в коде

**Правила:**
- ✅ **Чтение разрешено** — для понимания схемы данных
- ❌ **Модификация запрещена** — без явного `✅ Принято`
- ⚠️ **Изменение схемы коллекций** — требует миграции (риск потери данных)
- 🚫 **Логирование токенов AstraDB** — абсолютно запрещено

**Примеры запрещённых действий:**

## 🛡️ ПРОЦЕДУРА РАБОТЫ С КРАСНЫМИ ЗОНАМИ

### Шаг 1: Идентификация
Перед модификацией файла проверить:
```bash
# Проверка, является ли файл красной зоной
grep -E "backend/auth|backend/core/db|scripts/deploy|\.github/workflows|wallet\.py|tonconnect\.js|\.env\." <<< "$FILE_PATH"
```

### Шаг 2: Запрос разрешения
Если файл в красной зоне:
1. Прочитать файл
2. Подготовить точечный diff
3. Объяснить причину изменения
4. Показать diff НейроКодеру
5. Дождаться `✅ Принято`

### Шаг 3: Применение
Только после получения `✅ Принято`:
1. Применить diff
2. Запустить `node scripts/pre-deploy-check.js`
3. Показать результат верификации
4. Дождаться подтверждения деплоя

## 🚨 НАРУШЕНИЯ И ПОСЛЕДСТВИЯ

**Если агент модифицирует красную зону без разрешения:**
1. Немедленная остановка работы
2. Откат изменений через `git reset --hard`
3. Анализ причины нарушения
4. Обновление инструкций агента

**Если агент логирует секреты:**
1. Немедленная ротация всех затронутых ключей
2. Аудит логов на предмет утечек
3. Блокировка агента до исправления
