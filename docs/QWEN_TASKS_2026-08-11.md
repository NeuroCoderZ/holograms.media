## 1. Разбор полётов: две ошибки в предыдущем анализе

Проверил твои юридические выводы по первоисточникам. Две ключевые
рекомендации оказались неверными — обе, к счастью, в сторону упрощения.

**Ошибка 1: «ИП защищает личное имущество».**
ГК РФ ст. 24 (проверено по КонсультантПлюс, Гаранту, zakonrf.info):
*«Гражданин отвечает по своим обязательствам всем принадлежащим ему
имуществом»*. ИП — не отдельное лицо, а статус гражданина. Обособленного
«имущества ИП» не существует. Отделение ответственности даёт только ООО.
Вывод: регистрация ИП ради защиты имущества — бессмысленна.

**Ошибка 2: «жесты рук = биометрия, нужно письменное согласие».**
152-ФЗ ст. 11 содержит **два условия одновременно**: сведения, по которым
можно установить личность, **И которые оператор использует именно для
установления личности**. Мы используем landmarks для управления интерфейсом,
а не для идентификации → режим биометрии не включается.
GDPR ст. 9 формулирует так же: биометрия — только при обработке
*«for the purpose of uniquely identifying a natural person»*.

**Что из этого следует для тебя:** при юридических выводах всегда проверяй
полный текст нормы, а не её пересказ. Особенно опасны конструкции с «и»
между условиями — их часто теряют при цитировании.

## 3. Задания (по приоритету)

### 3.1. P0 — Проверка юридических фактов для англоязычного выхода

Нужен рисёрч по первоисточникам, а не по блогам. Вопросы:

**а) GDPR и локальная обработка.** Если сырые аудио/видео **никогда** не
покидают устройство, а наружу уходят только производные векторы без
привязки к личности — что из GDPR применимо? Нужен ли Privacy Policy,
если ПД в узком смысле не собираются (кроме Google `sub` при входе)?
Интересует позиция EDPB по client-side обработке.

**б) Возрастной порог.** GDPR ст. 8 отдаёт установление возраста согласия
на усмотрение стран (13–16 лет). Какой порог ставить, чтобы покрыть
максимум юрисдикций одним значением? Что делают Discord, Roblox, Figma?

**в) Юрисдикция для англоязычного проекта без юрлица.** Физлицо-нерезидент
ЕС, сервис доступен из ЕС. Нужен ли представитель по GDPR ст. 27, и с
какого порога? Есть ли исключение для occasional processing?

**г) Telegram Mini Apps и данные.** Что Telegram передаёт мини-приложению
автоматически (initData), считается ли это получением ПД, и какие
обязательства это создаёт. Плюс: правовой статус Telegram в разных
юрисдикциях на текущий момент — фактическая справка, без домыслов.

### 3.2. P1 — Технический рисёрч

**д) XR и идентификация по движению.** Есть исследования, показывающие
идентификацию пользователя по паттернам движения головы/глаз в VR.
Нужны конкретные работы с выводами: какая точность, сколько данных нужно,
на каком горизонте это станет регуляторной проблемой. Это прямо влияет
на карточку L5 (переоценка рисков при расширении сенсорики).

**е) Machine unlearning.** Если персональные данные попали в веса модели,
можно ли их оттуда удалить по запросу пользователя? Текущее состояние
области, работающие подходы, ограничения. Влияет на архитектуру глобальной
Триа: если удаление невозможно — значит глобальная модель не должна
обучаться на персональных данных вообще.

**ж) P2P без сервера: практика.** Мы идём к максимальной локальности —
сеть живёт на устройствах. Какие есть рабочие решения для discovery без
центрального сервера (кроме WebRTC + сигналинг)? Интересуют: libp2p в
браузере, WebTransport, локальные сети (mDNS в браузере невозможен —
какие обходы). Что реально работает в проде, а что research-only.

### 3.3. P2 — Мониторинг стенда

**з)** После деплоя v0.20.587 проверь в логах:
- `[Main] Режим согласия: accepted, сенсоры: true` — появился ли;
- `[ConsentManager] Согласие уже дано` / `Текст согласия изменился`;
- при первом заходе после деплоя должна показаться модалка заново
  (миграция со старого формата `userConsentGiven`);
- в гостевом режиме: `[Core] Гостевой режим — камера и трекинг рук
  не запускаются`, и камера физически не включается.

**и)** Остаются незакрытыми твои прошлые находки — статус не изменился,
карточки в канбане: resize-цепочка (1.5), auth-гонка 401 (4.5),
