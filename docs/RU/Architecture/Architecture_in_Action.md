# Архитектура в Действии: От Вейвлетов до Голограмм

Этот документ описывает текущую, работающую архитектуру проекта Holographic Media, соединяя её с нашими визионерскими целями. Мы строим будущее, прочно стоя на фундаменте работающего кода.

## Общая Схема

Проект представляет собой клиент-серверное веб-приложение с мощным ядром для аудио-анализа, выполняемым на стороне клиента, и гибким бэкендом, развернутым на современной облачной инфраструктуре.

1.  **Клиент (Frontend):** JavaScript (ESM) и Three.js, развернутые на **Cloudflare Pages**. Отвечает за захват аудио, его анализ с помощью WASM-модуля, визуализацию голограммы и взаимодействие с пользователем.
2.  **Ядро Аудио-Анализа (holocore):** Модуль на Rust, скомпилированный в WebAssembly (WASM). Выполняется в браузере для максимальной производительности.
3.  **Бэкенд (Backend):** Приложение на FastAPI (Python), развернутое на **Koyeb**. Отвечает за API, WebSocket-соединения и бизнес-логику.
4.  **База данных (Database):** **AstraDB** (на базе Cassandra) для хранения данных пользователей, голограмм и т.д.
5.  **Хранилище (Storage):** **Backblaze B2** для хранения медиа-файлов и других крупных объектов.
6.  **Дополнительные сервисы:** **Cloudflare Workers** и **R2** могут использоваться для вспомогательных задач и кэширования.

## 1. Каноническое Ядро (`holocore`): Слышать как Мозг

**Визионерская цель:** Создать систему, способную воспринимать и обрабатывать звук не как цифровой поток, а как многомерное явление, подобно слуховой коре головного мозга.

**Текущая реализация:** Ядро `holocore` реализует **Непрерывное Вейвлет-Преобразование (CWT)** с использованием вейвлета Морле. На выходе `holocore` предоставляет два ключевых параметра для каждой частотной полосы:
*   **Уровень громкости (dB):** Энергия частоты в данный момент.
*   **Фазовый сдвиг (Pan Angle):** Разница фаз между левым и правым каналом, позволяющая определить положение звука в пространстве.

## 2. Визуализация (`hologramRenderer.js`): Танец Фотонов

**Визионерская цель:** Преобразовать сложные потоки данных в интуитивно понятные, живые аудиовизуальные образы — голограммы.

**Текущая реализация:** Модуль `hologramRenderer.js` управляет сценой на базе Three.js. Он получает данные от `holocore` и в реальном времени обновляет 3D-объекты, изменяя их **глубину** и **положение** в зависимости от громкости и панорамы звука.

## 3. Бэкенд и Аутентификация (`backend/`): Разум в Облаке

**Визионерская цель:** "Триа" — полноценный ИИ-партнер, а также безопасная и надежная среда для взаимодействия пользователей.

**Текущая реализация:** Бэкенд на FastAPI предоставляет REST API и WebSocket для взаимодействия в реальном времени.
*   **Аутентификация:** Реализована через стандартный протокол **OAuth 2.0 от Google**. Клиент получает ID токен от Google, отправляет его на эндпоинт `/api/v1/auth/google`. Бэкенд верифицирует этот токен и выпускает собственный **JWT-токен** для дальнейшей авторизации всех запросов к API, включая WebSocket-соединения.
*   **ИИ "Триа":** Логика взаимодействия с ИИ инкапсулирована в сервисах, которые могут обращаться к различным LLM через API.

## 4. Децентрализованная Коммуникация (`NetHoloGlyph`)

**Визионерская цель:** Создать "цифровой векторный котёл" для прямого обмена голограммами между пользователями (P2P).

**Текущая реализация:** В `hologramRenderer.js` интегрирован клиент `netHoloGlyphClient`, который использует **WebRTC**. Бэкенд предоставляет WebSocket-эндпоинт для сигнализации, необходимой для установки P2P-соединения.
