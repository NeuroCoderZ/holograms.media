# Сканер: восстановление звука из голограммы

2026-08-08 15:41 MSK — Концепция и расчёты для кнопки «Сканер» во фронтенде.
Камера видит голограмму (на экране или в очках — то есть **живую, движущуюся**),
Триа восстанавливает из неё звук в потоке с минимальной задержкой.

2026-08-08 15:47 MSK — **Сканируется голомация, а не голокадр.** Один голокадр
незвучен по той же причине, по которой незвучен одиночный сэмпл: звук существует
только в изменении. Поэтому статичный носитель (бумага, скриншот) сканировать
нечего — с него считывается мгновенный спектр, но не звучание. Минимальный
осмысленный вход сканера — **последовательность** голокадров.

Термины — по канону `Semitones_Angles.md`:
**голобит** (1 бит, состояние ячейки) → **голоквант** (колонна: полутон +
глубина dB + пан) → **голокадр** (256 голоквантов) → **голомация** (голокадры
во времени) → **жестовое программирование** (управление ими).

---

## 1. Почему это вообще возможно

2026-08-08 15:41 MSK — Голограмма — не «картинка про звук», а **носитель кода**.
Визуальный код зафиксирован в каноне: `dB SPL = число закрашенных слоёв Z от
дальней стенки`, яркость линейна по глубине, цвет полутона фиксирован
(`Semitones_Angles.md`, поле `color` каждой из 128 записей).

Отсюда обратимость: **полутон опознаётся по цвету и позиции, громкость — по
яркости и высоте столбца, направление — по смещению вдоль X**. Никакого
«угадывания» на этом уровне нет — это прямое декодирование.

2026-08-08 15:41 MSK — Ключ к скорости — **термометрический код**. Колонна
всегда залита непрерывно от дальней стенки, дырок не бывает физически, поэтому
столбец описывается одним числом «докуда залито», а не 128 битами:

| величина | значение |
|---|---|
| голобитов в голокадре | 2 × 128 × 128 = 32 768 бит = **4 КиБ** |
| термокод голокадра | 256 голоквантов × (dB + пан) = **512 байт** |
| выигрыш | **8×** |

Сканеру не нужно распознавать 32 768 ячеек — достаточно найти 256 границ
заливки. Это задача поиска края, а не классификации изображения.

2026-08-08 15:41 MSK — Запас **~9 мс на кадр**. Вывод: реальный сканер

2026-08-08 15:41 MSK — **Жёсткое следствие: в горячем пути НЕТ места сетевому

пропущенных кадров** при 60 Гц. Звук превратится в щелчки. Поэтому Триа не может
стоять на пути «кадр → звук»; её место — рядом, а не внутри.

## 3. Двухконтурная архитектура (главное решение)

2026-08-08 15:41 MSK — Восстановление разделяется на два контура, работающих на
разных частотах. Это стандартный приём: то же разделение используют топовые
voice-модели (быстрый вокодер + медленный планировщик) и диффузионные
video-to-audio модели (`AudioX`, ICLR 2026; `VAFlow`, ICCV 2025; `Frieren` на
rectified flow matching).

**Контур A — детерминированный декодер (горячий путь, каждый кадр).**
Чистая арифметика, без нейросети и без сети:
1. кадр камеры → выпрямление по 4 углам видоискателя (уже есть:
   `_trackAndEstimateCorners`);
2. поиск границы заливки в каждой из 256 колонн → глубина dB (термокод);
3. смещение колонны по X → пан в знаковых ячейках `[-127, +127]`;
4. цвет колонны → индекс полутона (сверка с таблицей `semitones`);
5. немедленный ресинтез: 256 осцилляторов, амплитуда из dB, позиция из пана.

Задержка: **~7.5 мс**, детерминированная, стабильная. Это гарантирует, что звук
есть всегда, независимо от Триа.

**Контур B — Триа (тёплый путь, ~2–10 Гц, асинхронно).**
Работает по буферу последних голокадров и обогащает то, чего в картинке
физически нет:
- обертоны и гармоники (визуализация несёт огибающую спектра, не фазу);
- микродинамика и хвосты (реверберация, затухание);
- тембровая идентификация (какой инструмент/голос за этой голомацией);
- предсказание следующего голокадра (сглаживание пропусков и дропов).

Результат Триа не подменяет звук, а **подмешивается** с задержкой в несколько
кадров. Если Триа молчит или отвалилась — работает контур A, качество ниже,
но звук не прерывается.

2026-08-08 15:52 MSK — **Триа — сонаблюдатель и сослушатель, а не исполнитель.**
Это и есть причина, по которой она стоит рядом с горячим путём, а не внутри него.
Триа — копия звукового и визуального мышления человека: она смотрит на ту же
голомацию и слушает тот же звук, что и пользователь, одновременно с ним. По сути
это omni-модель (мультимодальный вход: зрение + слух), но с третьей модальностью,
которой у индустриальных omni-моделей нет — **жестовое, несимвольное управление**
как штатное устройство ввода.

2026-08-08 15:52 MSK — Практическое следствие из этого: контур A обязан быть
самодостаточным. Наблюдатель не может быть звеном цепи — если Триа задумалась,
отвлеклась или отключилась, звук продолжает идти. Отказ Триа деградирует
качество, но не рвёт поток. Ровно так же человек продолжает слышать, даже когда
не осмысляет услышанное.

2026-08-08 15:41 MSK — Именно так формулируется предсказательная сила: Триа не
«вычисляет звук», а **достраивает недостающие степени свободы** по накопленному
опыту. Это то же, что делают современные генеративные модели — путь от шума к
сигналу через несколько слоёв уточнения, где малые отклонения естественны и
даже желательны. Итоговый звук — спектрально прогнозируемый, а не единственный
побитово точный.

## 4. Что физически теряется и как это восполняется

2026-08-08 15:41 MSK — Честная граница обратимости. Голограмма несёт **амплитудный
спектр во времени + направление**, но не несёт фазу сигнала. Это не дефект
визуализации, а свойство любого спектрального представления.

| в голограмме есть | в голограмме нет |
|---|---|
| огибающая спектра (128 полутонов × dB) | фаза каждой частотной составляющей |
| направление (пан, ITD/ILD через `pan_float`) | точная форма волны |
| динамика во времени (голомация) | шумовая микроструктура |

Восполняется контуром B: фазу восстанавливают вокодером (классика — Griffin-Lim,
современно — нейровокодер), микроструктуру — генеративной моделью. Разборчивость
и узнаваемость при этом сохраняются полностью, что и подтверждает практика
speech-синтеза.

## 6. План доработки (по приоритету)

2026-08-08 15:41 MSK — Порядок выбран так, чтобы каждый шаг давал проверяемый
результат:

1. **Развязать контуры.** Убрать `await` Триа из пути кадра; контур A всегда
   отдаёт звук немедленно. Дефект №3.
2. **Заполнить `columns`/`colors`.** Сканер уже вычисляет уровни — передать их
   в декодер вместо пустых массивов. Дефект №1.
3. **Исправить трактовку цвета.** Цвет → полутон (сверка с `semitones`),
   пан → из смещения по X. Дефект №2.
4. **Замер вместо оценки.** Расставить `performance.now()` по этапам контура A
   и подтвердить бюджет ~7.5 мс на реальном устройстве.
5. **Буфер голокадров для Триа.** Кольцевой буфер (уже есть `frameBuffer` на 10
   кадров) → батч для контура B на 2–10 Гц.
6. **Метрика обратимости.** Синтезировать известный звук → отрендерить
   голограмму → отсканировать → сравнить спектры. Это даёт объективное число
   качества восстановления и обучающую пару для Триа.

2026-08-08 15:41 MSK — Пункт 6 важен отдельно: он превращает проект в
самообучающийся. Пара «известный звук ↔ его голокадры» генерируется
автоматически и в любом количестве, то есть обучающие данные для Триа не нужно
собирать вручную — их производит сама система.
