# Стандартная процедура создания эмбеддингов Триа (Standard Embedding Procedure)

## 1. Понятие "ГолоКванта" (HoloQuant)
В основе интеллекта Триа (Triple-A) лежит **ГолоКвант** — атомарная, неделимая единица голографической информации, представленная в виде 1536-мерного вектора (Codestral-Embed).

### Унифицированный пайплайн:
`Входные данные` -> `Пре-процессинг (BasilaQ-256)` -> `Векторизация (Codestral-1536)` -> **HoloQuant** -> `Astra DB`

## 2. Типы данных и их дискретизация

### 2.1. Программный код (Code Layer: "Source HoloQuant")
- **Инструмент**: `repomix-context.xml`.
- **Процедура**: Бэкенд парсит XML, используя теги `<file path="...">`. Каждый файл или крупный блок кода превращается в отдельный ГолоКвант.
- **Метаданные**: В HoloQuant зашивается путь к файлу, хэш содержимого и версия проекта.

### 2.2. Текстовые интенты (Text Layer)
- **Инструмент**: Chat API / Whisper (для аудио).
- **Процедура**: Текст очищается от шума. К нему добавляется мета-информация о текущем состоянии интерфейса (Active UI State).
- **Результат**: Вектор 1536d, связывающий слова с элементами управления.

### 2.3. Мультимодальный поток (Modal Layer: "Sensor HoloQuant")
- **Инструмент**: BasilaQ-256 (WASM).
- **Процедура**: Сырые тензоры жестов и аудио-вейвлеты "шредируются" алгоритмом Базилак.
- **Результат**: Генерируется серия ГолоКвантов, описывающая динамику интенции пользователя 120 раз в секунду.

## 3. Слои Эволюции (Evolutionary Layers)

| Слой | Описание | Частота обновления |
| :--- | :--- | :--- |
| **Local** | Текущий контекст разработчика (черновики). | Real-time / Hot-reload |
| **Source** | Утвержденный код в GitHub (dev branch). | С каждым камитом |
| **Build** | Скомпилированные и развернутые ассеты. | С каждым деплоем |
| **Personal** | Индивидуальный опыт и жесты пользователя. | С каждой сессией |

## 4. Процедура "Снимка Сессии" (Offline Snapshot)
Когда пользователь завершает работу:
1. Персональная Триа агрегирует все эмбеддинги, созданные в режиме **Training Mode**.
2. Вычисляется "дельту" (изменение) между состоянием "До" и "После".
3. Формируется компактный **Snapshot** — векторный отчет о потребностях и достижениях пользователя.
4. Snapshot отправляется в Глобальную Триа для анализа и пополнения **Стека Задач**.
