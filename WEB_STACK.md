## 1) Цель: целостность, а не заплатки

Текущий код — **гибрид**, где Three.js держит сцену/камеру/рендер, а поверх него
вторым canvas native WebGPU рисует голограмму. Это даёт **несогласованность**:
две несинхронизированные камеры, два рендера, три рендерера в дереве. Переезд
делается не «выпиливанием Three.js по файлу», а **переносом всей архитектуры на
единый стек**, где каждый слой имеет одну ось ответственности.

### Три раздельные оси (сейчас свалены в Three.js и спутаны)

| Ось | Технология | Что решает | Где живёт |
|-----|-----------|-----------|-----------|
| **Картинка (локальная)** | WebGPU | рендер голограммы каждому клиенту | `js/engine/*` (HoloEngine) |
| **Состояние (общая)** | WebRTC + WebSocket | синхронизация поз/жестов/эха между пользователями | `js/services/netHoloGlyphClient.js` |
| **Доступ к устройству (иммерсивность)** | WebXR | VR/AR-сессии, поза гарнитуры | `js/xr/*` |

**Принцип:** WebGPU рисует, WebRTC/WebSocket синкают, WebXR открывает устройство.
Каждый слой независим, связаны только через явный контракт состояний.

## 2) Слои целевого стека

| Слой | Файлы (целевые) | Замена сейчас | Роль | Зависит от |
|------|---------------|---------------|------|-----------|
| **Ядро рендера** | `js/engine/Engine.js`, `HologramWebGPU.js`, `InstancedColumns.js`, `GridWireframe.js`, `columns.wgsl.js` | Three.js рендер + WebGPURenderer(`three/examples`) | один canvas, одна камера-источник, свои шейдеры (WGSL), свой рендер-луп | WebGPU |
| **Граф сцены** | `js/engine/*` (группы примитивов) | `THREE.Scene` + 8 потребителей в `js/3d/*` | тор/параллелепипед/колонки/сетка/сферы/эхо — ~6 примитивов; без менеджера графа | Ядро |
| **Вход/жесты** | `js/core/gestures.js`, `js/gestures/*` | mediaPipe + gestureManager → Three scene | контроль камеры (drag/wheel/pinch), жесты; единый контракт | ядро |
| **Пикинг** | HoloEngine (свой луч в ячейку) | `THREE.Raycaster` в `SmartHologram.js` | выбор объектов графа по pan/depth из dynamic-буфера | ядро |
| **XR** | `js/xr/*` → `navigator.xr` + `XRGPUBinding` | `webxr_session_manager.js` (через `renderer.xr`) | VR/AR-сессии, поза гарнитуры как источник камеры | WebXR + ядро |
| **Мультиплеер** | `js/services/netHoloGlyphClient.js` | сырой P2P (`EarthZero` эхо от пиров) | WebSocket (сигналинг) → WebRTC DataChannel「hologlyph-data」= общее состояние | WebRTC/WS + граф |

## 3) Потоки данных (должны стать согласованными)

```
ИСТОЧНИКИ СТАТУСА → ЕДИНАЯ КАМЕРА → РЕНДЕР
  gestures (drag/wheel/pinch) ─┐
  XR-поза гарнитуры ───────────┼──→ HoloEngine.camera (одна) → WebGPU render
  сеть (чужие позы/эхо) ──────┘

СИНХРОНИЗАЦИЯ (общее состояние):
  локальная поза/жесты → WebRTC DataChannel → остальным клиентам
                                             → их EarthZero / их камера
```

**Контракт состояния** (единый объект, которым обмениваются):
- поза (yaw/pitch/zoom) или точка интереса
- позиции эха (peerId → x/y/z/intensity) — сейчас в `EarthZero`
- жесты (тип, параметры)

## 4) Связный порядок переноса (безопасный, «с умом»)

Ключ: **не ломать работающее**. Сцена Three не может исчезнуть, пока слои
(EarthZero/жесты) живут в `state.scene` и рендерятся через `state.renderer`.
Поэтому порядок — по связности, а не «выпилить ортокамеру».

| Шаг | Что | Связность | Критерий зелёного |
|-----|-----|-----------|-------------------|
| **1** ✅ DONE | Контроль камеры без Three (drag/wheel/pinch → `Engine`) | убирает Three.js из входа | жесты двигают нативную камеру |
| **2** | Одна камера-источник: `state.camera` ↔ HoloEngine синхронны | убирает «2 камеры» | нет независимой Three-камеры для рендера слоёв |
| **3** | Портировать слои (EarthZero, жесты) на граф HoloEngine | **разблокирует удаление `THREE.Scene`** | EarthZero/жесты рендерятся нативным графом |
| **4** | Удалить `THREE.Scene`/`OrthographicCamera` из sceneSetup | перенос сцены завершён | слои рисует HoloEngine, Three-сцена не нужна |
| **5** | Нативный picking (луч в ячейку) | убирает `THREE.Raycaster` | выбор в нативном графе |
| **6** | XR нативно: `navigator.xr.requestSession` + `XRGPUBinding` | убирает `renderer.xr` | XR-сессия по стандартному веб-API |
| **7** | Мультиплеер: контракт состояния WebRTC/WS над портом слоёв | синхронизация становится общей | чужие позы/эхо синкаются через DataChannel |
| **8** | Вычитка Three-импортов по модулю | механическая | grep по Three пуст в `js/` |
| **9** | Финал: `three` из `package.json`, `renderBackend='webgpu'` по умолчанию | Phase 4 | Three не импортируется, WebGPU стабилен |

## 5) Что НЕ делаем (границы)

- Не переписываем «всё разом» — приложение должно работать на каждом шаге
- Не держим два рендерера дольше, чем нужно для переноса слоёв
- Не тянем Three.js «для окружения» — резервный план отменён (10.08)
- Как правило, не удаляем данные/модули без бэкапа и контракта зеленого
